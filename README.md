# VPS init

Скрипт первичной настройки свежего VPS на **Debian / Ubuntu**: обновление системы, пользователь с SSH-ключами, харденинг SSH, UFW, Fail2ban, Docker.

Запускать **один раз** на чистом сервере, от **root**.

## Быстрый старт

### 1. Отредактируй `init.sh` локально

В начале файла задай:

| Переменная | Описание |
|------------|----------|
| `NEW_USER` | Имя нового пользователя (sudo без пароля) |
| `SSH_PORT` | Порт SSH после настройки |
| `SSH_PUB_KEYS` | Массив публичных ключей (`ssh-ed25519 …`, `ssh-rsa …`) |

Убедись, что **хотя бы один** ключ — твой, иначе после скрипта root по SSH отключён, а по паролю войти нельзя.

### 2. Скопируй на сервер и запусти

С локальной машины (подставь IP и текущий порт SSH провайдера, часто `22`):

```bash
scp -P 22 init.sh root@<IP_СЕРВЕРА>:/root/
ssh -p 22 root@<IP_СЕРВЕРА>
chmod +x /root/init.sh
/root/init.sh
```

Либо одной командой без сохранения файла на диске:

```bash
ssh root@<IP_СЕРВЕРА> 'bash -s' < init.sh
```

(`chmod` не нужен — bash читает скрипт из stdin.)

### 3. После завершения

1. **Не закрывай** сессию, где шёл скрипт, пока не проверишь вход.
2. В **новом** терминале:

   ```bash
   ssh -p <SSH_PORT> <NEW_USER>@<IP_СЕРВЕРА>
   ```

3. Если вход по ключу успешен — перезагрузка: `sudo reboot`.
4. Лог установки: `/home/<NEW_USER>/vps_setup.log`.

## Что делает скрипт

1. `apt update` + `apt full-upgrade`, базовые пакеты (`curl`, `wget`, `nano`, `ufw`, `sudo`)
2. Создаёт пользователя, кладёт ключи в `~/.ssh/authorized_keys`
3. `sudoers`: NOPASSWD для `%sudo`, убирает `#includedir`
4. SSH: новый порт, только ключи, `PermitRootLogin no`
5. UFW: правила для SSH / 80 / 443 — **файрвол не включается** (строка закомментирована)
6. Fail2ban: конфиг под твой SSH-порт — **сервис не запускается** (закомментировано)
7. Docker через [get.docker.com](https://get.docker.com), пользователь в группе `docker`

При необходимости после проверки SSH включи вручную:

```bash
sudo ufw --force enable
sudo systemctl enable --now fail2ban
```

## Требования

- Debian или Ubuntu с `apt`
- Первый вход на сервер как **root** (или `sudo -i` до запуска)
- Доступ в интернет (обновления, Docker)

## Важно

- Смена порта SSH и отключение root — **сразу после шага 4**. Держи открытую сессию root до успешного теста с новым портом и пользователем.
- Повторный запуск на уже настроенном сервере частично идемпотентен (пользователь не пересоздаётся), но повторный харденинг SSH и перезапуск сервисов могут быть нежелательны.
- Секреты и приватные ключи в репозиторий не коммить — только публичные ключи в `SSH_PUB_KEYS`.
